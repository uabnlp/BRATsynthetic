Title: Envs + evaluation stabilization (legacy → Py3.9, spaCy 3.4.1), setup scripts, docs, and fixes

Summary
- Stabilize the legacy evaluation environment on Python 3.9 with spaCy 3.4.1 + scispaCy 0.5.1 (medspaCy 1.2.0 compatible), pin numeric/typing deps, and keep nmslib optional to avoid Ubuntu build issues.
- Add setup scripts for both environments, improve evaluation utilities, and align documentation.

Changes
- Legacy environment
  - requirements-eval-legacy.txt: pin spaCy==3.4.1, scispaCy==0.5.1, medspaCy==1.2.0; pin numpy==1.23.5, scipy==1.10.1; add pydantic==1.10.2, typing_extensions==4.4.0, pathy==0.10.1; nmslib optional (commented).
  - scripts/setup_env_legacy_eval.sh: target python3.9 (or pyenv 3.9.18); optional SCISPACY_MODEL install; clearer guidance.
  - EVALUATION.md/README.md: update legacy matrix, model link (en_core_sci_sm 0.5.1), and run examples.
- Main environment
  - scripts/setup_env_main.sh: convenience script for Python 3.12 + spaCy 3.8 + en_core_web_lg.
- Evaluation utilities
  - evaluation/medspacy2txt.py, evaluation/medspacy_evaluation.py, evaluation/displacy_test.py: improved CLI, sentencizer fallback if PyRuSH missing, consistent output dirs, minor robustness fixes.
- Core improvements
  - bratsynthetic.py: file logging and tqdm-safe error logging; progress handling tweaks.
  - bratsynthetic/BratSyntheticConfig.py: absolute path resolution, output dir creation, clearer validation messages.
- Housekeeping
  - requirements-evaluation.txt → requirements-eval-legacy.txt, requirements.txt → requirements-main.txt renames.
  - .gitignore updates for venvs, local outputs, evaluation/Displays.

Rationale
- medspaCy 1.2.0 requires spaCy >=3.4.1,<3.6 and en_core_sci_sm 0.5.1 requires spaCy >=3.4.1,<3.5. Pinning spaCy 3.4.1 satisfies both. NumPy 1.23.x + SciPy 1.10.x avoid thinc ABI issues; pydantic/typing_extensions/pathy pins resolve spaCy 3.4.x typing errors. Making nmslib optional prevents Ubuntu build failures where the linker isn’t needed.
